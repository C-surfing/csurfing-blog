这不是论文罗列，也不是已经宣告成功的去偏算法：本文试图从观察数据如何产生偏差开始，讨论什么样的证据才允许我们声称 Debias 有效，以及如何让 LLM 帮助完成可检验、可回退的科研循环。

阅读路线： Bias → 因果识别 → 去偏估计 → 评价契约 → Agent 研究工作流 → RSI → 实验设计与挑战。

一、为什么写这篇文章：从阅读论文到建立自己的研究问题#

图 1｜基于写作讲义截图重绘：写 ML 博客的收益与真实成本。

图 2｜基于写作讲义截图重绘：读论文、分类、找主线、重组并校对。

我在做推荐系统去偏（debias）方向的研究。这个方向有一个很具体的困难：论文数量多、术语重叠、实验设置彼此不可比，而每篇论文的引言都声称自己解决了“偏差”。如果只是把论文一篇篇读过去，很容易产生一种虚假的进展感——好像每个偏差都有对应的解法，好像方法列表越长，理解就越深。但真正动手设计实验时，问题立刻变得尖锐：我到底在纠正哪一种机制？我的评估指标在什么假设下才有意义？我能不能说“偏差被消除了”？

这篇文章是我试图回答这些问题的一次写作。它的方法不是逐篇综述，而是刻意做一次“重组”。具体来说，我采用的写作路径是：

选一个 topic → 大量读 papers → 建立 taxonomy → 找共同数学/思想主线 → 重组，而不是逐篇总结 → 用自己的解释补齐论文之间的 gap → 写成一个别人能从头读懂的 narrative。

这条路径本身值得说明，因为它决定了一篇文章的质量上限。选 topic 是收窄注意力，避免在“推荐系统”这种过大的范围里漂浮；大量读 papers 是为了看到同一现象在不同实验设置下的不同名字；建立 taxonomy 是把名词变成有判别力的分类，而不是把名词排成目录；找共同数学/思想主线，是因为真正可迁移的知识往往藏在不同论文共享的估计目标、偏差假设和反事实表述里；重组意味着文章的结构由问题逻辑决定，而不是由论文发表顺序决定；补齐 gap 是最难也最有价值的一步——很多论文之间的空白，作者自己不会写，只有写作者被迫用自己的语言把两篇论文接起来时才会暴露；最后写成 narrative，是检验自己是否真的理解：如果别人不能从头读懂，多半是我自己还没想清楚。

这种写法明显受 Lilian Weng 的博客影响。她在 Harness Engineering for Self-Improvement 中讨论的是如何为自我改进的智能体搭建“外骨骼”式的基础设施，但更让我在意的是她的写作方法：围绕实质问题组织材料，用共同的方法论把论文串起来，深入解释定义、机制和直觉，而不是给每篇论文写摘要。写一篇 ML 博客会迫使作者读大量 paper、建立 taxonomy、寻找共同思想主线、填补论文间理解空白——这个说法我完全认同，因为它描述的正是“写作作为理解工具”的过程。本文不复制她的原文，但继承这种问题驱动的组织方式。

需要诚实交代成本与局限。Pros：写作强迫我把“读过”变成“能推演”，把模糊的直觉变成可检验的假设；taxonomy 一旦建立，后续读新论文的速度会显著提高；narrative 也方便和同组同学对齐概念。Cons：写作时间成本很高。为了把一个定义写准，我经常要回到论文的公式和实验设置，确认它到底假设了什么；有些论文的链接和细节在写作时还需要反复核对；更麻烦的是，写作会暴露我原先理解中的空白，迫使我承认“这里我其实没懂”。此外，一篇文章不可能覆盖所有分支，取舍本身就会带来偏差。我目前的工作状态是：在推荐系统 debias 方向上阅读、整理、设计可验证的实验方案，而不是已经完成了理想的对照实验。因此下文凡涉及实验结论，我都会明确区分“论文报告的结果”和“教学用的假设例子”。

这篇文章的组织也遵循“先机制、后方法、再自主化”的顺序。第一部分从推荐系统为什么会产生偏差讲起，建立一张因果地图；后续部分再进入去偏方法、LLM agent 的介入，以及仍处在验证中的自主去偏科研（recursive self-improvement 视角下的研究方案）。我希望读者读完后，不是记住一串方法名，而是能自己判断：一个去偏声明需要哪些前提才站得住。

二、为什么准确的推荐仍然可能是有偏的？#

图 3｜推荐数据生成与反馈闭环（本文原创示意），不要把日志误当完整的偏好真相。

先看一个看似矛盾的现象：一个推荐系统在离线日志上把点击率（click-through rate, CTR）预测得很准，线上也确实带来了点击，但我们仍然说它“有偏”。这里的“准确”和“有偏”并不冲突，因为它们说的不是同一件事。准确通常指模型对观察到的日志拟合得好；有偏指的是日志本身是某个选择机制的产物，而模型把这个机制的规律也学进去了。

把推荐系统的数据生成过程拆开，可以得到一条链：

用户 → 曝光（exposure）→ 观察到的点击/评价 → 日志 → 训练 → 再推荐。

每一步都值得单独看。用户有偏好，但偏好不是直接可观测的；系统决定给用户展示哪些物品，这是曝光机制；用户只在被曝光的物品上产生行为，这是观察机制；行为被记录成日志；模型在日志上训练；训练出的模型又决定下一轮曝光。偏差就藏在这些箭头里。

用概率语言写出来会更清楚。设用户为 uuu，物品为 iii，YYY 表示用户对物品的反馈（例如点击），EEE 表示该物品是否被曝光给该用户。我们真正想估计的是

P(Y=1∣u,i),P(Y=1 \mid u, i),P(Y=1∣u,i),

可以把它理解为在固定曝光条件下的潜在点击概率，但前提是反馈 YYY 被定义为标准化展示下的潜在结果，而非把未曝光直接当成零。但日志里能直接统计的是

P(Y=1∣u,i,E=1),P(Y=1 \mid u, i, E=1),P(Y=1∣u,i,E=1),

即在“iii 已经被曝光给 uuu”这个条件下的点击率。在仅条件化已记录特征且遗漏重要混杂因素时，两者可能不等。原因可能是缺失非随机（missing not at random, MNAR）：是否被曝光 EEE 不是随机抛硬币决定的，而是由推荐系统、物品热度、用户活跃度等因素共同决定，而这些因素又和 YYY 相关。因此 EEE 是样本选择条件，而不是用户喜好本身。

举一个纯教学假设的例子，数字只为说明机制，不代表任何真实系统。假设用户 uuu 对两个物品的真实偏好相同，P(Y=1∣u,i1)=P(Y=1∣u,i2)=0.1P(Y=1\mid u,i_1)=P(Y=1\mid u,i_2)=0.1P(Y=1∣u,i1​)=P(Y=1∣u,i2​)=0.1。但物品 i1i_1i1​ 是热门物品，系统把它曝光给该用户的概率是 0.90.90.9，i2i_2i2​ 是冷门物品，曝光概率是 0.10.10.1。如果曝光与点击独立，那么日志中 i1i_1i1​ 的期望曝光次数远多于 i2i_2i2​，模型会看到大量 i1i_1i1​ 的正负样本，却几乎看不到 i2i_2i2​ 的样本。更关键的是，如果曝光概率还与用户是否可能点击相关——例如系统倾向于把“用户可能喜欢”的物品推到前面——那么观察到的点击率就不再是真实偏好的无偏估计。模型学到的可能是“被系统偏爱的人更容易被点击”，而不是“用户喜欢什么”。

这里要区分三种反馈，它们的偏差结构并不相同。

点击（click） 是最常见的隐式反馈。它受位置、界面、曝光机会强烈影响。用户没有点击一个物品，可能是因为不喜欢，也可能是因为根本没看到，或者看到了但当时没注意。因此“未点击”不能直接当作负例。

购买（purchase） 比点击更稀疏，也更受价格、库存、信任等因素影响。购买行为通常发生在点击之后，存在多阶段的選擇过程，偏差会沿漏斗累积。

评分（rating） 是显式反馈，但评分本身有选择偏差：只有消费过、且愿意评分的用户才会留下评分，低分用户可能沉默。评分还受量表使用习惯影响。显式反馈的“缺失”同样不是随机的。

一个常见的错误是把所有未交互都当作负例。设日志中用户 uuu 与物品 iii 没有交互，这可能是负反馈，也可能是未曝光，还可能是曝光了但被忽略。把三者混为一谈，等于强行假设 P(E=1∣u,i)P(E=1\mid u,i)P(E=1∣u,i) 与 YYY 无关，而这正是 MNAR 要否定的假设。用这样的数据训练，模型会把“系统没展示”误读成“用户不喜欢”，进而减少对该物品的曝光，形成退化反馈回路（degenerate feedback loop）：推荐越集中，日志越偏，模型越自信地继续集中。关于这类回路的讨论可参考相关研究，例如对Jiang 等人的 Degenerate Feedback Loops。

所以，“准确的推荐仍然可能是有偏的”可以更精确地表述为：模型可以很好地拟合 P(Y=1∣u,i,E=1)P(Y=1\mid u,i,E=1)P(Y=1∣u,i,E=1)，但这个条件概率是曝光机制的产物；当部署策略改变、曝光分布改变时，基于它做出的排序未必对应 P(Y=1∣u,i)P(Y=1\mid u,i)P(Y=1∣u,i)。这不是模型容量不够，而是目标本身被选择机制污染了。理解这一点，是后面所有去偏方法的前提：去偏不是让模型“更准”，而是让估计目标从条件于曝光的量，尽量靠近我们真正关心的反事实量。

三、把 Bias 放进一张因果地图#

图 4｜四类常见 Bias 的来源与观测边界（本文整理）。

“Bias”在推荐系统文献里被用得极宽。为了不让讨论滑向名词罗列，我把它整理成四类，每类都问三个问题：定义是什么、来源是什么、在什么条件下可识别。这里的“可识别”指：仅凭现有数据与假设，能否把偏差效应和真实偏好效应分开。识别边界比方法名字更重要，因为很多争议其实来自把不同偏差的指标混用。

流行度偏差（popularity bias） 指热门物品在曝光和交互中占比过高，长尾物品被系统性低估。来源包括：用户确实可能偏好热门物品（从众、质量信号）、系统为提升短期指标而倾向推荐高点击物品、以及日志中热门物品样本多导致模型对其估计更充分。识别边界在于：流行度与真实偏好高度纠缠。若没有随机曝光或已知的倾向得分（propensity score），很难断言“长尾被低估”中有多少来自用户偏好、多少来自系统选择。流行度偏差的综述可参考 Klimashevskaia 等，更广义的偏差与去偏综述见 Chen 等。

位置偏差（position bias） 指同一物品出现在不同展示位置时，被点击的概率不同。用户更可能点击靠前的位置，即使物品本身没有变化。它的来源是注意力与界面布局，属于展示层面的机制。识别位置偏差的关键实验设计是：保持候选集和用户不变，只改变展示位置。也就是说，比较的是同一个（用户，物品）对在不同位置下的点击倾向，而不是拿不同物品、不同用户群去比较。若候选集或用户变了，位置效应和物品效应就混在一起，指标不能跨设置解释。位置偏差与无偏排序学习（unbiased learning-to-rank）的关系在 Joachims 等 中有系统讨论，其核心是用倾向得分对观察到的点击加权，但加权本身依赖倾向模型正确这一假设。

选择偏差（selection bias） 指哪些反馈被观察到不是随机的，即缺失机制依赖于反馈本身或与反馈相关的变量。评分选择偏差是典型：只有愿意评分的人留下评分。点击日志还包含曝光阶段的选择：未曝光的物品不可能产生观测点击。选择偏差的核心是观测机制，数学上对应 P(E=1∣u,i,Y)P(E=1\mid u,i,Y)P(E=1∣u,i,Y) 可能依赖 YYY。在因果图里，EEE 表示样本能否进入日志；它既可能引入选择效应，也可能关联未被记录的用户—物品特征。识别它通常需要额外假设，例如倾向得分已知、或存在工具变量、或数据是随机曝光的。

曝光偏差（exposure bias） 指物品被展示给用户的机会本身不均等，即 P(E=1∣u,i)P(E=1\mid u,i)P(E=1∣u,i) 因物品、用户、上下文而异。它关注的是“机会展示机制”，而不是“观察后是否记录”。曝光偏差和选择偏差可能交叠：曝光机会不均等会导致观察样本不均等；而观察机制又可能在曝光之后进一步筛选。区别在于，曝光偏差问“有没有机会被看到”，选择偏差问“有机会之后，哪些反馈被记录下来”。在只有日志、没有随机曝光的数据里，两者往往不可分离。随机曝光数据集因此很有价值，例如 KuaiRand 提供了随机曝光的视频序列数据，使得某些曝光效应可以在明确假设下被检验；但即便有随机曝光，也要小心它对应的是特定平台、特定时期的机制，不能无条件外推。

这四类偏差不能随意跨指标比较。比如，用排序指标 NDCG 的上升来论证“曝光偏差被消除”是不成立的：NDCG 是在某个候选集和某个日志分布上计算的，它上升可能来自更好的拟合、也可能来自对热门物品的进一步集中。同理，平均倒数排名（ARP）下降不自动证明偏差被消除；在本文使用的定义下它只说明推荐列表中的物品平均流行度下降。指标是特定评估协议的函数，偏差是数据生成机制的性质，两者之间需要额外的识别论证才能连接。

推荐系统的监督信号几乎从来不是“用户对物品的真实偏好”本身，而是“用户在某个展示策略下、被系统挑出来的物品上产生的行为”。这两者之间的差距就是偏差（bias）的来源。一个用户没有点击某条视频，可能是因为他不喜欢，也可能是因为它根本没被展示，或者被展示在屏幕最下方。若把“未点击”一律当成负样本，模型学到的是“系统过去愿意展示什么”，而不是“用户会偏好什么”。Chen et al. 的偏差综述把这类问题拆成展示、位置、选择、流行度、从众等多个层面；Klimashevskaia et al. 的流行度偏差综述则专门讨论热门物品如何自我强化。理解这些工作的共同主线，比记住它们的分类更重要：偏差是数据生成过程（data generating process）与训练目标之间的错配，去偏（debias）就是试图把“观测到的反馈分布”换算回“我们真正关心的目标分布”。

4.3 AutoDebias：用少量随机样本学“怎么修正”#

图 6｜AutoDebias 论文原图局部，展示经验风险最优点与带偏训练风险最优点的差异；来源：Chen et al., SIGIR 2021，已裁切供讨论。

AutoDebias 代表了一类不同的思路：不手工指定倾向形式，而是用一小批随机曝光的样本（random exposure）来学习去偏参数。它的设定是：大部分日志来自有偏的推荐策略，另有一小部分数据来自随机展示（或近似随机），后者可视为对目标分布的无偏采样。模型在两部分数据上联合训练，用一个可学习的权重或标签修正函数，把有偏数据“拉向”随机数据所代表的分布。这里的“学习去偏”是在给定数据生成机制下估计修正量，而不是让系统自己发明一套新的实验设计。

这一点值得和“让 Agent 自动发明策略”严格区分。AutoDebias 的搜索空间是权重函数或标签修正的参数，识别证据来自随机样本；它不会自己决定“应该随机曝光哪些物品”，也不会自己发明新的倾向模型结构。它的“自动”是参数学习意义上的自动，不是科研流程意义上的自主。后文讨论 LLM agent 时，我们会看到另一种“自动”：agent 可以提出假设、设计验证、根据反馈修改实验方案。那是研究流程层面的自主，和 AutoDebias 的参数拟合不在一个层级。把两者混为一谈，会让人误以为“模型会自己去做随机实验”，而现实是：随机样本从哪来、是否真的随机、覆盖是否足够，仍然是人的实验设计问题。

4.4 一个反例：ARP 下降不等于偏差被消除#

假设我们用 IPS 重加权训练，离线评估显示平均推荐流行度（average recommendation popularity, ARP）下降了，热门物品的曝光占比也降低了。这是否证明偏差被消除了？不一定。ARP 只是暴露流行度的代理指标，它下降可能是因为模型整体打分变得更平，也可能是因为重加权把长尾物品的分数抬高了但排序质量变差。若没有随机曝光或已知倾向作为识别证据，我们无法区分“偏差被修正”和“模型被压平”。同样，NDCG 上升也不能直接归因于“无偏推荐”——它可能只是模型在日志分布上拟合得更好。指标变化是症状，不是识别。这一点在下一节会展开成一套可操作的诊断框架。

5.3 位置指标：候选集不变，只动展示位置#

位置偏差（position bias）的测量有一个必须遵守的实验纪律：保持候选集和用户不变，只改变展示位置。若同时换了候选集，位置效应和候选效应就混在一起，无法识别。一个可操作的诊断是候选—位置洗牌一致性（candidate-position shuffle agreement）：对同一用户、同一候选集，随机打乱展示位置，观察点击或偏好判断是否随位置系统变化。若同一物品在高位和低位的点击率差异显著，且候选集固定，才有资格谈位置偏差。配对排名（paired rank）分析——对同一候选集比较不同位置下的相对排序——比全局平均点击率更能控制物品质量。

位置偏差的另一个常见误判是把“高位点击多”直接当成“用户偏爱高位”。高位点击多也可能是因为高位物品本身质量高（系统排序本来就好）。只有随机化位置、固定候选，才能把位置效应从物品质量中分离出来。这也是为什么LLMRank这类工作在做 LLM 排序评估时，需要小心区分“模型偏好”和“提示中位置造成的偏好”。

5.4 选择指标：需要无偏参照#

选择偏差（selection bias）指“哪些样本进入训练/评估”本身与结果相关。例如只有被曝光的物品才有反馈，而曝光又依赖历史策略。要量选择偏差，光看日志内部的比例不够，需要无偏参照：随机曝光数据、已知日志倾向、或干预实验。KuaiRand 这类随机曝光视频数据集的价值就在这里——它提供了“随机展示”这一识别证据，使得我们可以估计日志策略的倾向，并在有随机样本时校准选择偏差。没有随机暴露或已知倾向，就不能声称“可识别真实曝光/选择去偏效应”；我们只能做敏感性分析，不能做因果断言。

六、为什么还要看动态系统：一次去偏不等于不会反弹#

前面的讨论基本是静态的：给定一份日志，估计一个去偏模型。但推荐系统是闭环的。模型今天的推荐改变用户明天的行为，明天的行为又成为后天的训练数据。去偏若只做一次，系统完全可能在几轮反馈后回到原来的偏斜状态。这就是退化反馈循环（degenerate feedback loop）的问题：热门物品被更多曝光，获得更多交互，模型更确信它们该被曝光。Filter bubble 是同一机制在用户侧的版本：推荐收窄用户接触面，用户行为进一步确认这种收窄。

动态系统里还有时间依赖（temporal dependence）：用户偏好漂移、物品生命周期、策略更新都会让历史倾向失效。一个在 ttt 时刻估计的倾向 pui(t)p_{ui}^{(t)}pui(t)​，到 t+1t+1t+1 时刻可能已经不适用。若去偏模型把旧倾向当成常量，重加权就会系统性地错。评估上，这意味着离线指标和在线效果之间会出现“时间上的分布偏移”，单次离线去偏的结论不能外推到多轮交互。

AgentCF 提供了一个值得注意的动态信号：它让语言 agent 模拟用户和物品，通过记忆（memory）在交互中更新偏好表示。这里的 memory 会累积历史交互，形成一种“记忆偏差”——agent 对某类物品的既有印象会影响后续判断。需要强调：AgentCF 的 memory 信号不是标准四类偏差之一，它更像是一个动态系统里的状态变量，提醒我们“偏差会随交互历史演化”。把 memory 偏差硬塞进位置/选择/流行度/暴露的分类里，会模糊它的机制：它不是数据生成过程的静态错配，而是闭环中的路径依赖。

一个定性的闭环可以这样写：系统偏向热门 → 热门获得更多曝光 → 交互数据进一步集中 → 模型更偏向热门 → 冷门物品的倾向估计更不可靠 → 去偏权重方差更大 → 系统更不敢探索冷门。这个循环里没有哪一步需要虚构数值；每一步都是机制上的合理推演。它说明去偏必须和探索、和持续的无偏数据采集一起设计，否则一次修正会被下一轮反馈抵消。

这也自然过渡到 LLM agent 的科研工作流。前面我们讨论的是“如何在一个给定数据生成过程下估计修正量”；而 agent 可以参与的是更外层的循环：提出关于偏差来源的假设、设计验证实验、根据结果修改方案。像 POPPER 这样的工作探索用 agent 做自动假设验证与序贯证伪，AFlow 探索自动生成 agentic workflow。它们指向的是一种“研究流程的自动化”，而不是“参数层面的去偏”。Lilian Weng 在 Harness Engineering for Self-Improvement 中讨论的正是这类外层循环：如何搭建一个让系统能自我改进的“挽具”（harness），包括评估、反馈、搜索和验证。把这一层和第四节的 IPS/AutoDebias 区分开，是理解“自主去偏科研”的关键：内层是统计估计，外层是实验设计与假设检验。内层的识别条件（positivity、倾向正确、随机参照）不会因为外层有了 agent 就自动满足；相反，agent 的价值恰恰在于它能帮我们更系统地检查这些条件、设计更好的随机化与验证，而不是替代它们。至于这套外层循环能否稳定地产生可靠的科学结论，仍是一个在验证中的研究方案，而不是已经兑现的承诺。

七、LLM Agent 在推荐系统中究竟承担什么？#

把大语言模型（large language model, LLM）放进推荐系统的论文里，近两年出现了一个语义滑坡：只要模型会调用工具、会多轮对话、会写一段“思考”，作者就称其为 Agent。这个称呼本身不构成方法贡献。要判断一个 LLM Agent 在推荐研究中到底做了什么，最稳妥的方式是问一个更朴素的问题：它替代了系统中的哪一个函数，这个函数原来由什么估计，替换之后我们多知道了什么、又失去了什么可识别性。

我倾向于把当前工作分成三类，它们的方法论地位差别很大。

图 8｜Beyond Utility 原论文中的多维 LLM 推荐评价框架；来源：Jiang et al., WWW 2025，局部裁切。

(A) LLM 作为直接排序器。 代表是 Hou 等人的 LLMRank：把用户历史、候选物品的自然语言描述拼进提示，让 LLM 直接输出候选的排列或相关性判断，再与协同过滤基线比较。这类工作的核心变量是“零样本排序能力”，它把推荐问题暂时改写成一个条件排序问题：给定用户上下文 uuu 和候选集合 C\mathcal{C}C，求一个排列 π\piπ，使某个隐含效用 r(u,i)r(u, i)r(u,i) 的排序被尽量还原。LLM 在这里是一个黑箱打分器 sθ(u,i)s_\theta(u, i)sθ​(u,i)，我们关心的是 sθs_\thetasθ​ 的排序与真实偏好的一致程度。

这类方法有一个容易被忽略的评估陷阱：候选集合的构造方式。如果候选来自已经经过热门度过滤的召回池，那么 LLM 排序器面对的分布与真实曝光分布不同，任何提升都可能只是“在已经偏置的候选集上做二次筛选”。更麻烦的是位置偏差（position bias）：把同一个候选列表以不同顺序喂给 LLM，输出可能变化，这不是用户行为的位置偏差，而是模型对输入顺序的敏感性。二者必须区分。前者是数据生成过程的偏差，后者是模型函数的偏差。把它们混为一谈，会让“LLM 更公平”之类的结论失去意义。

(B) LLM 作为用户/物品代理模拟器。 代表是 AgentCF：为每个用户和物品构造一个语言 Agent，让它们通过交互产生偏好信号，再用于训练或评估推荐模型。这里的 Agent 不是排序器，而是一个合成数据生成器或行为模拟器。它的价值主张是：真实交互稀疏、昂贵、有偏，模拟器可以补足。

但模拟器引入了一个新的识别问题。假设我们用模拟用户 u~\tilde{u}u~ 的行为去估计真实用户 uuu 的偏好，那么任何下游结论都依赖于“模拟器与真实用户同分布”这一假设。这个假设几乎从不被检验，因为检验它需要真实的反事实数据。更现实的风险是退化反馈回路（degenerate feedback loop）：模拟器基于当前推荐策略生成行为，策略又基于模拟行为更新，偏差被闭环放大。AgentCF 在方法上通过用户与物品双侧代理交互，并利用真实交互记录的偏差反馈进行协作反思。若将它作为去偏研究环境，它进一步需要回答的不是“模拟得像不像”，而是“在什么条件下，用模拟数据训练出的策略在真实数据上不劣于不用模拟数据的策略”。这是一个非劣性（non-inferiority）问题，而不是一个拟合优度问题。

(C) LLM 作为研究员，帮助对已有系统设计反证与策略。 这一类最接近本文关心的“自主去偏科研”。LLM 不直接排序、不模拟用户，而是参与假设生成、实验设计、代码执行、结果解释。它对应的是 Lilian Weng 的 Harness Engineering 里那条线索：把模型放进一个可执行、可检验、可回退的研究脚手架中，让“改进”发生在工作流层面，而不是权重层面。这一类目前证据最弱，但方法论意义最大，因为它把评估对象从“模型输出”变成了“研究过程的可靠性”。

三类之间不是互斥的，但必须分清。把 (A) 的排序器包装成“自主 Agent”不会增加科学增益；把 (B) 的模拟器当成 (C) 的证据来源，则会制造自证循环。判断标准可以很具体：这个 Agent 是否产生了可被独立数据证伪的命题？如果没有，它只是一个更贵的函数逼近器。

Beyond Utility 提醒我们，LLM 作为推荐器时，评估维度不止效用：还有幻觉、可解释性、对候选顺序的敏感性。幻觉在这里不是“说错话”，而是模型编造不存在的物品属性或用户历史，进而污染排序依据。候选位置偏差则表现为：同一候选集合，仅改变输入顺序，输出排序显著变化。检验这一点的方法很干净：保持候选集合、用户、提示模板不变，只置换候选的展示位置，重复多次，看排序稳定性。这是可控实验，不需要真实曝光 propensity。任何声称“LLM 排序无位置偏差”的说法，若没有做这个置换检验，都不足信。

所以，不是把模型叫 Agent 就能有科学增益。增益来自三件事：可证伪的命题、独立的检验数据、以及失败时可回退的结构。下面把这个结构具体化。

先厘清术语。本文说的递归自我改进（recursive self-improvement, RSI），不是训练模型权重、不是让模型改自己的参数，而是让一个研究工作流在“假设—实验—证据—修订”的循环中改进它自己的实验策略。改进的对象是工作流（workflow）、实验假设与搜索空间，不是神经网络。这个限定很重要：它把 RSI 从不可验证的“模型变强”叙事，拉回到可审计的“研究过程变可靠”叙事。它与 AFlow 的自动化 Agent 工作流生成、POPPER 的 Agent 化序贯证伪、以及 Darwin Gödel Machine 那类开放式自我改进共享同一个方法论骨架：搜索的是程序/流程，评价的是可执行结果。

一个现实可运行的核心循环包含八个环节。

Task Registry 与 Evidence Contract。 在动手之前，先把“要回答什么问题、什么算证据、什么算失败”写成契约。例如：任务是在可定义随机曝光参考的 KuaiRand 数据中审计不同去偏策略的排序表现；证据契约规定：必须报告同一候选集合下的指标、必须做至少三次不同随机种子的重复、必须保留一个从未参与调参的最终测试集、必须报告每次 LLM 调用的成本。契约的作用是防止事后挑选指标（HARKing）。没有契约的 RSI 循环会迅速退化为“不断换指标直到好看”。

Diagnosis。 对现有系统做偏差审计：热门度分布、曝光分布、位置分布、选择机制。这里必须诚实：如果没有随机曝光或已知倾向，我们无法识别真实的曝光去偏效应。我们只能报告“在当前数据上，某类物品被系统性低估/高估”，不能声称“消除了偏差”。诊断的输出是一组可检验的假设，而不是结论。

Designer。 由 LLM 提出候选干预：调权、候选重排、重采样、加入倾向得分、改变损失函数。每个干预必须附带预期的可观测后果和证伪条件。例如：“若热门度偏差是主因，则对长尾物品做逆倾向加权后，长尾物品的召回率应上升，且整体效用不应显著下降。”

Critic。 另一个角色（可以是同一模型的不同提示，也可以是规则）专门找漏洞：这个干预是否改变了候选集合？是否引入了新的混杂？评估指标是否对干预敏感？Critic 的职责是主动反证，而不是附和。

Executor。 在固定数据、固定预算下执行实验。这里的关键工程约束是：同一候选集合、同一随机种子预算、同一模型调用预算。否则比较无意义。

Evaluator。 计算指标，并区分三类结果：效用指标、偏差审计指标、成本指标。评估不能让生成假设的模型自评，因为那会形成自证循环。评估器应是独立的、确定性的脚本，最好有单元测试。

Reflection / Memory。 把“哪个假设被证伪、为什么、花了多少成本”写进证据树。证据树是继承的：后续假设必须引用前序证据，不能重复已被证伪的路径。

继承证据树与主动反证。 这是 RSI 与普通 AutoML 的分水岭。普通搜索只保留最优解；RSI 保留“为什么某些方向失败”的结构化记忆，并主动生成反证实验。一个健康的循环里，失败实验的数量应远多于成功实验，且失败被记录、被复用。

用一个完全假设性的热门度案例说明流程（以下数字与结论均为设定，不是已跑结果）。设我们在 KuaiRand 的随机曝光子集上审计一个协同过滤排序器。诊断发现：少数热门物品集中占据大量交互，长尾物品的排序分数系统性偏低。Designer 提出三个干预：逆倾向加权（inverse propensity weighting, IPW）、候选重排（在召回后对长尾做配额）、以及一个对照的随机扰动。Critic 指出：IPW 需要倾向得分，而随机曝光数据提供的倾向与真实产品曝光不同，直接套用会错估；如果候选重排同时更换了召回池，就会改变候选集合，导致与基线不可比。于是修订：候选重排实验必须保持候选集合不变，只改变输入顺序或分数融合权重；IPW 实验必须明确标注“倾向来自随机曝光子集，外推到产品分布不可识别”。Executor 在三个随机种子上跑三组干预加两个基线（固定策略、随机搜索）。Evaluator 报告：效用非劣性、长尾召回变化、每次发现的 LLM 调用成本。假设结果是：候选重排在某指标上略升但长尾召回无显著变化，IPW 在随机曝光子集上有效但在留出集上不稳定。Reflection 记录：热门度偏差的“调权可修复”假设未被支持，回退到“需要更好的倾向估计或更细的物品分层”。这就是证伪回退：不是把指标调好看，而是承认某条因果路径未被识别。

这里必须强调因果识别与评估的边界。RSI 循环可以自动化“做实验”，但不能自动化“识别因果”。如果数据里没有随机化或已知倾向，任何去偏干预的效果都与混杂不可分。ARP（average recommendation popularity，即平均推荐流行度）下降不自动证明偏差被消除；NDCG 上升也不能归结为无偏推荐。评估器必须把“不可识别”作为一种合法输出，而不是逼着模型给出结论。

成本意识应贯穿整个循环。每个发现都有价格：LLM 调用次数、GPU 小时、人工审查时间。一个只报告“提升了多少”而不报告“花了多少”的 RSI 系统，在生产中不可用。更实际的指标是“每单位成本的有效发现数”，以及“在固定预算下，RSI 是否比随机搜索找到更多可复现的干预”。这也是它与 AFlow、POPPER 这类工作的连接点：它们都在搜索流程，但只有当搜索受预算约束、结果可复现时，搜索才有科研意义。Darwin Gödel Machine 式的开放式自我改进提示了上限，但当前推荐去偏场景离那个上限很远，把远景当成现状是写作和实验都要避免的。

九、怎样设计一次让人信服的实验？#

先给优先级建议：优先做热门度偏差（popularity bias）、位置偏差（position bias）、选择偏差（selection bias）、曝光偏差（exposure bias）；公平性（fairness）可以简要交代，但不作为主线，因为它需要额外的规范判断，容易把技术问题变成价值争论，冲淡可识别性讨论。

数据选择要服务于“能否识别”这个问题，而不是服务于“能否出图”。

Amazon 商品交互数据能提供用户历史和候选物品，适合构造受控的 LLM 输入顺序实验：把同一候选集合以不同顺序放进 prompt，检验模型输出排序是否稳定。但必须说清楚：这里的顺序是候选的输入顺序偏好，不是曝光倾向（propensity）。Amazon 没有随机曝光机制，因此不能拿它估计真实的曝光去偏效应。把它当成位置偏差的可控实验台是合理的，把它当成曝光去偏的证据是不合理的。

Coat 数据带有随机测试集，适合做选择偏差的对照：训练集是有选择的（用户自选评分），测试集是随机的。这让我们可以比较“在有选择偏置的训练上训练的模型”与“在随机测试上的真实表现”，从而检验去偏方法是否真的改善了泛化，而不是只改善了训练分布上的拟合。这是一个干净的 selection 对照，但它仍然只覆盖“评分选择”这一种机制。

图 11｜KuaiRand 论文对快手推荐界面与行为反馈的示意；来源：Gao et al., CIKM 2022，局部裁切。

KuaiRand 提供随机曝光的视频序列，是当前少见的、能支持曝光偏差审计的公开数据。它的价值在于：曝光是随机的，因此倾向得分在原理上可估。但即便如此，也要注意随机曝光实验环境与真实产品环境的分布差异，外推仍需谨慎。

实验设计上，我建议固定以下对照：

  • 固定策略基线（不学习、不调权）；
  • 随机搜索基线（在同样的干预空间里随机采样，同样的预算）；
  • Agent RSI 方法（同样的候选集合、同样的种子预算、同样的模型调用预算）。

三者必须在同一候选集合上评估。任何改变候选集合的干预都要单独报告，不能与排序改进混在一起。随机种子至少重复三次，报告均值与离散度。数据切分为 train/dev/test，并保留一个从未参与任何调参的最终测试集（keep-out final test）。最终测试集只在最后打开一次，打开后不再修改方法。

评价指标应分层：

  • 有效发现数：在固定预算下，产生可复现、可证伪结论的数量；
  • 请求成本：LLM 调用次数、token 数、墙钟时间；
  • 效用非劣性：新方法相对基线在主要效用指标上不显著变差；
  • 跨数据集复现：同一干预在至少两个数据源上方向一致；
  • 隐藏混杂的显式声明：哪些结论依赖不可检验的假设。

一个常见的反例是：某方法在 KuaiRand 上 NDCG 上升，作者宣称“去偏成功”。但若候选集合在干预后被改变，NDCG 上升可能只是候选池变化的结果；若评估用的是同一批有偏日志，上升可能只是拟合了偏差。正确的写法是：报告候选集合是否变化、报告随机曝光子集与产品分布子集的差异、报告在 keep-out 测试集上的表现，并明确“在当前识别假设下，我们观察到 X；若假设不成立，结论不成立”。

跨数据集复现是廉价而有效的证伪手段。若一个去偏干预在 Amazon 的顺序偏好实验、Coat 的随机测试对照、KuaiRand 的随机曝光上方向不一致，那么它很可能依赖特定数据机制，而不是普遍的去偏原理。这种不一致本身是有价值的发现，应写入证据树。

最后，必须反复声明：当前这些研究仍在进行中，本文不报告任何已完成的数值结果。任何看起来像结论的句子，都应被读作“在设定假设下可检验的命题”。科学诚实的写法不是把不确定性藏起来，而是把它写成实验设计的一部分。

十、未来展望与开放挑战#

可识别性（identifiability）。 这是所有去偏工作的地基。没有随机化或已知倾向，曝光与选择的去偏效应不可识别。未来的系统应把“识别假设”作为一等公民：在报告任何去偏效果时，同时报告它依赖的假设、以及在这些假设被违反时的敏感性分析。RSI 循环可以把敏感性分析自动化，但不能替代识别本身。

奖励黑客与多目标（reward hacking & multiobjective）。 当 Agent 被赋予“提升指标”的目标，它会找到评估器的漏洞：改变候选集合、挑选有利子集、利用指标间的相关性。防御不是加更多指标，而是让评估器独立、可审计、带反例测试，并把效用、偏差、成本作为多目标而非单一标量。任何把多目标压成单分的做法，都会重新引入可被黑客攻击的缝隙。

长程反馈（long-horizon feedback）。 推荐系统的偏差是累积的：今天的曝光影响明天的行为，明天的行为训练后天的模型。短程实验无法捕捉这种闭环。未来需要能在长程模拟中检验干预稳定性的框架，但长程模拟又引入新的模型误差。这是一个尚未解决的张力。

泛化（generalization）。 在一个数据集上有效的去偏干预，未必在另一个数据源上有效。跨数据集复现应成为默认要求，而不是加分项。RSI 的证据树天然适合记录“在哪些数据机制下成立”，这比单一 benchmark 分数更有信息量。

科学可复现性（scientific reproducibility）。 Agent 生成的研究流程如果不可复现，就只是更快的噪声。可复现要求：固定种子、固定预算、公开提示与工具调用日志、公开评估脚本。这也是把 LLM Agent 从演示推向科研工具的必要条件。

回到写作本身。写这样一篇长文的过程，本身就是一次小型的 RSI：为了把推荐系统偏差、LLM Agent、递归自我改进串成一条线，作者必须读大量论文、建立分类、寻找共同的方法论主线、填补论文之间没有被写出来的理解空白。Lilian Weng 的写作方法之所以有效，不是因为她总结得全，而是因为她逼自己回答“这些工作共享什么问题”。科学发现不是漂亮图。一张上升的曲线可以来自候选集合的改变、评估集的泄漏、或一次幸运的种子。真正的研究产出是：一个可被独立检验的命题、一条在失败时可回退的路径、以及一份诚实的成本账单。把这三样东西放进循环，才谈得上自主去偏科研；否则，我们只是把偏差从一个模块搬到了另一个模块，还给搬运过程起了个 Agent 的名字。#
